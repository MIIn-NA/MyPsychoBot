# MyPsychoBot

Курсовой проект — Telegram-бот для мониторинга психоэмоционального состояния студентов.

Бот анализирует сообщения, определяет состояние: норма, стресс или тревога — и подбирает рекомендации.

## Сейчас реализовано

- Приём сообщений через Telegram.
- Классификация состояния моделью RuBERT (дообучена на трёх классах).
- Явный демонстрационный режим `BOT_DEMO_MODE=1`: `MockModel` (ключевые слова).
- Базовые и контекстные рекомендации.
- Сохранение итоговых результатов анализа в SQLite `db/results.db`.
- Личная статистика через `/stats` и кнопку «Моя статистика 📊».
- Групповой отчёт в `StatisticsService`: количества и доли состояний по группе
  и периоду, PNG-график дневных долей; к интерфейсу Telegram пока не подключён.

## Планируется

- Подключение реальных учебных групп и доступа психолога к групповому отчёту.
- Графики и динамика состояний в Telegram.

## Запуск

Выполняйте команды из папки `MyPsychoBot`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Укажите токен Telegram-бота в `BOT_TOKEN` в файле `.env`, затем запустите:

```bash
python bot/main_bot.py
```

Файл `.env` и локальная база `db/results.db` исключены из Git.

## Модель RuBERT

Обученная модель весит около 700 МБ и в Git не хранится.

### Как скачать модель
1. Откройте папку на Google Диске:
   https://drive.google.com/drive/folders/1nt6WPqAEULUNJTv6Z0ElhfR5GhmrQ6Ch?usp=sharing
2. Скачайте архив с моделью и распакуйте его в корень проекта (`MyPsychoBot`) так,
   чтобы получилась структура:
```MyPsychoBot/
└── models/
└── rubert_classifier/
├── config.json
├── model.safetensors
├── inference_config.json
├── class_mapping.json
└── файлы токенизатора
```
3. Проверьте загрузку:
   ```bash
   python bot/classifier.py
   ```
   Должны вывестись порог уверенности и три примера с классами.

Без доступной RuBERT бот сообщает, что анализ сейчас недоступен.
Для демонстрации явно задайте `BOT_DEMO_MODE=1` в `.env`; по умолчанию режим выключен.

### Как обучить модель на коротких сообщениях

RuBERT принимает даже одно слово. Чтобы модель видела такие реплики при
обучении, добавляйте в `data/data.csv` строки с колонками `text,label`:
например, `Спокойно,0`, `Перегруз,1`, `Тревожно,2`. Метки: 0 — норма,
1 — стресс, 2 — тревога. Добавляйте примеры для всех трёх классов, включая
отрицания вроде «Не переживаю». Реплики без ясного контекста вроде «Плохо»
не стоит размечать наугад.

После изменения CSV переобучите модель и проверьте загрузку новых весов:

```bash
python bot/train_model.py
python bot/classifier.py
```

Новые веса сохранятся в `models/rubert_classifier/`. Перезапустите бота,
чтобы он их загрузил. В `results/training_results.json` раздел
`short_messages` показывает число тестовых реплик из 1–3 слов, долю верных
предсказаний, долю прошедших порог уверенности и точность среди них.
Для ручной проверки начните с `/start` и отправьте короткую реплику,
которой нет в датасете.

## Команда
- Настя — Telegram-бот и база знаний.
- Даша — модель классификации.
- Таня — решатель, хранение данных и статистика.

Результаты бота носят информационный характер и не являются диагнозом.

## Решатель без Telegram

Для автономного анализа достаточно стандартного Python:

```python
from bot.solver import Solver, SolverError
from bot.mock_model import MockModel
from bot.knowledge_base import KnowledgeBase

solver = Solver(MockModel(), KnowledgeBase(), threshold=0.60)
result = solver.solve("Я НЕ боюсь экзамена, но очень устал!")
print(result.to_message())
print(result.rule_id, result.explanation)
```

`Solver(model, knowledge_base)` сохраняет прежний вызов с двумя аргументами.
Порог можно задать через `threshold`; Telegram передаёт
`model.low_confidence_threshold` из загруженной конфигурации RuBERT.
При уверенности строго ниже порога результат предварительный.

Некорректный вход вызывает `TypeError` или `ValueError`, сбой модели или
некорректный прогноз — `SolverError`. При ошибке прогноза база знаний не вызывается.
`KnowledgeBase.get_recommendation(text, predicted_class)` возвращает строку совета.
`get_recommendation_with_metadata(text, predicted_class)` возвращает неизменяемый
`Recommendation` с полями `advice`, `rule_id`, `explanation`.

Проверки без Telegram и загрузки модели (требуются `aiosqlite`, `matplotlib`
и его зависимости из `requirements.txt`):

```bash
python3 -m unittest discover -s tests -v
```

Контекстные правила выбираются только для класса модели: больший приоритет
в `context_priorities` выигрывает, при равенстве используется порядок объявления
в `context_rules`. Конфликтующие идентификаторы и отсутствие правил журналируются
без исходного сообщения. При отсутствии правил возвращается нейтральный совет.

RuBERT проверяет число токенов со специальными токенами до вызова нейросети.
Лимит — минимум из `max_length` инференса и `max_position_embeddings` модели.
Превышение вызывает отдельную `TextTooLongError`; Telegram просит сократить
сообщение. Проверка действует и на объединённый текст после уточнения.

В диалоге предлагается одно уточнение предварительной оценки (текстом или кнопкой).
Повторная предварительная оценка завершает попытку и предлагает новый анализ.
В SQLite сохраняются только оценки, прошедшие порог; исходное описание остаётся
только в состоянии ожидающего уточнения и очищается по завершении или отмене.
Расхождение с диаграммой последовательности описано в [отчёте](WORK_REPORT.md).

## Хранилище результатов

`Storage()` использует только `db/results.db` относительно корня проекта,
независимо от каталога запуска. Явный путь можно передать через `Storage(path)`.
Перед Telegram polling `init_table()` создаёт каталог и таблицу, проверяет
обязательные колонки и добавляет индекс `(group_name, analysis_date)`.
Несовместимая схема останавливает запуск с понятной ошибкой; повторная
инициализация сохраняет записи.

Сохранение, личная статистика (`get_user_class_counts`) и групповые выборки
(`get_results`, через `StatisticsService`) используют один экземпляр `storage`.
`/stats` показывает количества и доли трёх классов только текущего пользователя.
Пустая статистика и ошибка чтения сопровождаются разными ответами.
Прежний метод `get_user_stats` сохранён как совместимый вызов нового метода.

`get_results(group, start_date, end_date)` проверяет реальные даты строго в формате
`YYYY-MM-DD` и порядок границ. Обе даты включаются; записи упорядочены по
`analysis_date, id`. Пустой список означает отсутствие подходящих записей,
ошибки чтения передаются вызывающему коду.

`StatisticsService.get_summary()` формирует агрегированный текстовый отчёт
с количествами и долями состояний либо сообщением об отсутствии данных.
Этот метод не загружает Matplotlib и не строит изображение.
`await service.get_report(group_name, start_date, end_date)` возвращает `GroupReport`:
`summary` — тот же текст, `chart_png` — PNG в памяти (или `None` при пустой выборке),
`daily_aggregates` — дневные количества и доли классов в порядке 0, 1, 2.
Текст и график строятся по одной выборке `Storage.get_results()`.
График показывает долю анализов каждого класса за день; дни без анализов
остаются разрывами, а повторные анализы одного студента считаются отдельно.
Это распределение анализов, а не доля студентов и не медицинская оценка риска.
Если наблюдения есть только за один день, сводка показывает распределение
и сообщает, что сравнивать динамику пока не с чем. PNG использует шкалу 0–100%,
три подписанные серии с различными маркерами и ограниченное число подписей дат
для длинных периодов. Каждый отчёт строится на собственной фигуре и содержит
только агрегаты; индивидуальные сообщения, советы, уверенность и идентификаторы
студентов в текст, изображение и `GroupReport` не включаются.
Для графика используется Matplotlib с Agg без GUI, временные файлы не создаются.
В сводке явно названы «число анализов» и «доля анализов». Доли за период
рассчитываются от общего числа анализов, дневные — от числа анализов этого дня;
округление применяется только при форматировании текста.
Некорректный запрос вызывает `ValueError`, повреждённые дата или класс записи —
`StatisticsDataError` (подкласс `ValueError`); сбои чтения и отрисовки передаются
вызывающему коду. Только успешная пустая выборка сопровождается текстом
«За выбранный период данных нет» с группой и датами и `chart_png=None`.

Проверка роли психолога и групповая команда в Telegram пока не подключены.
Будущий Telegram-обработчик должен проверить роль психолога **до вызова**
`get_report()` или группового `get_summary()`, следовательно, до запроса
к хранилищу. При отказе в доступе сервис и хранилище не вызываются.
Наличие `get_report()` — готовый программный контракт, а не подключённый
сценарий психолога. Сервис и хранилище проверку доступа не выполняют.
Личная `/stats` сохраняется и читает только количества текущего пользователя.
Ограничение: в боте пока задано `group=1`, поэтому все новые анализы относятся
к одной группе до подключения реальных учебных групп.

Корневой `psycho_bot.db` не используется и автоматически не переносится:
в старой схеме нет группы. Уже существующая совместимая `db/results.db`
продолжает использоваться. Каталог `db/` исключён из Git.

Для проверок хранилища требуется `aiosqlite` из `requirements.txt`;
тесты создают настоящие SQLite-базы во временных каталогах.
